A chef can only cook with ingredients that are close at hand. Computers have the same problem. The places where data is kept come in a ladder: the closer to the worker, the faster but the smaller.

## The storage ladder

<Sketch name="im-ch04-1" />

| In the kitchen | In the computer | Size | Time to reach |
|---|---|---|---|
| The chef's hands | **Registers** and **cache**, inside the chip | tiny | about a nanosecond |
| The counter | **Memory** (RAM) | gigabytes | about 100 nanoseconds |
| The fridge | **SSD** storage | terabytes | tens of microseconds, up to about 100 |
| The warehouse across town | **Network storage**, such as Amazon S3 or Google Cloud Storage | as big as you like | milliseconds |

<Note>

The times come from Jeff Dean's “numbers everyone should know” (2009) and SSD makers' data sheets. They are rough sizes, not exact values, and newer hardware is faster. What matters is the gaps: each step down the ladder is many times slower than the one above it.

</Note>

A nanosecond is a billionth of a second. A microsecond is a thousand nanoseconds, and a millisecond is a thousand microseconds. So reaching the warehouse can take a million times longer than reaching the chef's hands.

## The GPU has its own counter

A GPU does not use the computer's normal memory for its work. It has its own memory built in, right next to its workers. This is the **GPU memory** from Notebook #2: 24 GB on an L4, 80 GB on an H100, and so on. Everything the GPU works on, the model's weights and every conversation's KV cache, has to be on this counter.

Between the computer's normal memory and the GPU's memory there is a connection called **PCIe**. A modern PCIe connection (Gen5, 16 lanes) moves about 64 GB per second in each direction. That sounds fast, but as Chapter 7 shows, the GPU's own memory is far faster.

## Why loading a model takes time

<Sketch name="im-ch04-2" />

Before a model can answer anything, its weights must travel down the ladder: from the warehouse or the fridge, through the computer, over PCIe, onto the GPU's counter. For a model with 16 GB of weights, that is a lot of boxes to move. If the weights come from the internet or network storage, it can take minutes.

This is the slow start from Notebook #2, Chapter 7. Now you can see where the time goes, and why the fixes work: keep the weights closer (on a disk next to the GPU), or stream them in faster.

<Careful>

**Restarting a model server is never free.** Each restart moves all the weights again. Plan updates so that at least one copy keeps running while another reloads.

</Careful>

<NoSillyQuestions>

<QA q={"Why not make all memory as fast as cache?"}>

Fast memory is expensive, takes up space on the chip, and uses more power. So computers use a little very fast memory and a lot of slower memory, and try to keep the data they need right now in the fast part.

</QA>

<QA q={"Does the GPU need the computer's normal memory at all?"}>

Yes, but less for the model itself. The computer's memory and CPU load the weights, run the serving software, and handle requests. The heavy maths happens in the GPU with its own memory.

</QA>

<Takeaways>

- Storage comes in a ladder: cache, memory, SSD, network storage. Faster means smaller.
- Each step down the ladder is many times slower than the one above.
- The GPU has its own memory. The weights and KV cache must be there before it can work.
- Loading a model means moving all its weights down the ladder, which can take minutes.
- Keep weights close to the GPU to start faster.
