A 70B model in BF16 has about 140 GB of weights. An H100 has 80 GB of memory. It does not fit. The answer is to split the model across several GPUs. But splitting creates a new problem: the GPUs now have to talk to each other, a lot.

## Splitting one model

<Sketch name="im-ch08-2" />

The most common way is **tensor parallelism**, which Notebook #2 mentioned. Each GPU holds a slice of every layer. For each token, every GPU does the sums for its slice, then the GPUs swap their partial results before moving on to the next layer.

That swapping happens many times for every token. So the connection between the GPUs must be very fast, or the GPUs spend their time waiting for each other.

## Two kinds of connection

| Connection | What it links | Speed per GPU |
|---|---|---|
| **PCIe Gen5** (16 lanes) | A GPU to the rest of the computer | about 128 GB/s (64 GB/s each way) |
| **NVLink**, H100 | GPUs to each other | 900 GB/s |
| **NVLink**, Blackwell | GPUs to each other | 1.8 TB/s |

<Note>

Sources: NVIDIA's NVLink page and NVIDIA's Hopper architecture blog. Checked 26 October 2026.

</Note>

NVLink is NVIDIA's own direct link between GPUs. On an H100 it is about 7 times faster than PCIe Gen5.

## Why GPU servers come with 8

<Sketch name="im-ch08-1" />

The big NVIDIA GPUs are usually sold on a board of **8 GPUs**, called **HGX**. The 8 GPUs connect through **NVSwitch** chips, so any GPU can talk to any other at full NVLink speed. Inside one server, the 8 GPUs can work together on one large model almost as if they were one big GPU.

This is why cloud machines like AWS p5.48xlarge, Google a3-highgpu-8g and Azure ND H100 v5 all have 8 GPUs.

## Going bigger: a whole rack

NVIDIA's **GB200 NVL72** links **72** Blackwell GPUs and 36 Grace CPUs in one rack, all on NVLink. NVIDIA describes it as “a 72-GPU NVIDIA NVLink domain that acts as a single, massive GPU”. Systems like this are used for the biggest models.

## Between servers

When a job needs more GPUs than one NVLink group, servers talk over the data center network. That network is fast, but much slower than NVLink. Chapter 9 looks at it.

<Careful>

**Splitting is not free.** Two GPUs do not make a model twice as fast. Some time always goes to swapping results. Only split a model when it doesn't fit, or when you need more speed than one GPU can give. If a model fits on one GPU, one GPU per copy is usually the simplest and best choice.

</Careful>

<Think>

A 70B model in FP8 is about 70 GB. Would you split it across two H100s (80 GB each), or put it on one H200 (141 GB)? Think about the KV cache, and about the swapping.

</Think>

<NoSillyQuestions>

<QA q={"Can I split a model across GPUs that only have PCIe?"}>

Yes, and some cloud machines do this. It works, but it is slower than NVLink. For splitting across many GPUs, NVLink matters a lot.

</QA>

<QA q={"Is this the same as running two copies of the model?"}>

No. Running two copies (Notebook #2, Chapter 7) means each GPU has the whole model and serves different users. Splitting means several GPUs share one copy. You can do both: for example, 2 copies, each split across 4 GPUs.

</QA>

<Takeaways>

- When a model doesn't fit, split it across GPUs. The common way is tensor parallelism.
- Split GPUs swap results many times per token, so the link between them must be fast.
- NVLink connects GPUs directly: 900 GB/s on H100, 1.8 TB/s on Blackwell, versus about 128 GB/s for PCIe Gen5.
- GPU servers usually have 8 GPUs joined by NVSwitch. The GB200 NVL72 joins 72 in one rack.
- If a model fits on one GPU, keep it on one.

</Takeaways>
