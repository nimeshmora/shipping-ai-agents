## Where the money goes

You pay for GPUs by the hour, whether they are busy or not. So the two biggest cost levers are:

1. **Keep GPUs busy.** Batching many users onto one GPU (Chapter 7) makes each token far cheaper.
2. **Use the smallest model and number format that does the job well.** Fewer bytes to move means fewer GPUs for the same traffic.

Notebook #2, Chapter 9 has the full cost math.

## When a plain CPU is enough

Not everything in an agent needs a GPU. Botley's own code, the web server, the database and the tools all run happily on CPUs (Chapter 3). And if you use a managed model service, someone else runs the GPUs and you don't need any of your own.

You need GPUs of your own only when you run a model yourself. Notebook #2 helps you decide whether that's worth it.

## What Maya learned

<Sticky color="yellow" width="88%">

**Maya's notes from the tour**

- Every token needs every weight, so **memory bandwidth** sets the pace for each user.
- **Batching** shares each delivery of weights between users. That's why one GPU can serve many people.
- **Memory size** decides what fits: the model plus every conversation's KV cache.
- **FP8 and FP4** help because there are fewer bytes to move.
- Big models are **split across GPUs**, which need fast links like NVLink.
- GPUs live in **real buildings** with power and cooling limits. That's why they're scarce and expensive.

</Sticky>

<Takeaways>

- In most agents, the model writing its answer takes the most time, then the tools.
