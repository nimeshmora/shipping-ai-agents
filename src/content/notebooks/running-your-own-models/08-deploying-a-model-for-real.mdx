Now we build it. We will serve a small open-weight model with vLLM, run two copies on two GPU machines, and point Botley at it. Each step explains what the command does.

<Sketch name="rm-ch08-1" />

## What we are deploying

| Choice | What we use | Why |
|---|---|---|
| Model | `Qwen/Qwen3-4B-Instruct-2507` | Apache 2.0 license, not gated (no Hugging Face token needed), about 8 GB in BF16. |
| GPU | NVIDIA L4, 24 GB (A100 on Azure) | Small and cheap. The model fits with plenty of room for the KV cache. |
| Copies | 2 | So one machine can fail or be updated without Botley losing its model (Chapter 7). |
| Serving engine | vLLM, image `vllm/vllm-openai:v0.32.0` | A fixed version, not `latest` (Chapter 6). |

<Careful>

**Before you start:**

- **GPU quota.** New accounts often have no GPU quota (Chapter 4). Ask for enough for two GPU machines in your region, and do it first.
- **Cost.** GPU machines cost money every hour they run, even when idle. On EKS, two g6.xlarge machines cost about $1.61 per hour on demand, plus $0.10 per hour for the cluster. On GKE Autopilot, GPU pods are billed for the whole machine Autopilot picks, plus a management fee. The Azure recipe's one A100 machine costs about $3.67 per hour. Delete everything when you finish (the last step of each recipe).
- **Commands change.** These are correct as of October 2026. Check each tool's `--help` and the linked guides before you run them.

</Careful>

## Step 1: the parts that are the same everywhere

Create a namespace and a key that Botley must send with every request:

```bash
kubectl create namespace models
kubectl create secret generic vllm-api-key -n models \
  --from-literal=key="$(openssl rand -hex 24)"
```

Save this file as `vllm.yaml`. The comments explain each part:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm
  namespace: models
spec:
  replicas: 2                       # two copies (Chapter 7)
  selector:
    matchLabels:
      app: vllm
  template:
    metadata:
      labels:
        app: vllm
    spec:
      nodeSelector: {}              # each recipe below tells you what to put here
      containers:
        - name: vllm
          image: vllm/vllm-openai:v0.32.0
          args:
            - --model=Qwen/Qwen3-4B-Instruct-2507
            - --max-model-len=16384          # caps KV cache per chat (Ch. 3)
            - --api-key=$(VLLM_API_KEY)      # filled in from the secret
          env:
            - name: VLLM_API_KEY
              valueFrom:
                secretKeyRef:
                  name: vllm-api-key
                  key: key
          ports:
            - containerPort: 8000
          resources:
            requests:
              cpu: "3"
              memory: 12Gi
              ephemeral-storage: 30Gi        # room for the downloaded weights
            limits:
              nvidia.com/gpu: 1              # one whole GPU for each copy
          volumeMounts:
            - name: dshm
              mountPath: /dev/shm            # shared memory for vLLM (Chapter 7)
            - name: hf-cache
              mountPath: /root/.cache/huggingface
          startupProbe:                      # allow up to 15 minutes to load
            httpGet:
              path: /health
              port: 8000
            periodSeconds: 10
            failureThreshold: 90
          readinessProbe:                    # only send traffic when ready
            httpGet:
              path: /health
              port: 8000
            periodSeconds: 10
          livenessProbe:                     # restart it if it stops answering
            httpGet:
              path: /health
              port: 8000
            periodSeconds: 30
            failureThreshold: 3
      volumes:
        - name: dshm
          emptyDir:
            medium: Memory
            sizeLimit: 2Gi
        - name: hf-cache
          emptyDir:
            sizeLimit: 25Gi
---
apiVersion: v1
kind: Service
metadata:
  name: vllm
  namespace: models
spec:
  selector:
    app: vllm
  ports:
    - port: 80
      targetPort: 8000
```

<Note>

This file is based on vLLM's own Kubernetes guide. Because each machine in our recipes has only one GPU, and each copy asks for a whole GPU, the two copies always land on different machines. The weights download from Hugging Face each time a pod starts. Chapter 7 shows faster ways for later.

</Note>

<Think>

Why `--max-model-len=16384`? The model supports 262,144 tokens. Using Chapter 3's numbers (about 147 KB of KV cache per token), how much memory would one conversation that long need? Would it fit on a 24 GB L4?

</Think>

Official guide: “Deploy an AI model on AKS with the AI toolchain operator” (learn.microsoft.com/azure/aks/ai-toolchain-operator). ## Step 3: check it works

On GKE or EKS, open a tunnel from your laptop to the Service, then ask the model something. (For Azure, see the note after these commands.)

```bash
kubectl get pods -n models          # wait until both show READY 1/1
kubectl port-forward -n models svc/vllm 8000:80

# in a second terminal
KEY=$(kubectl get secret vllm-api-key -n models -o jsonpath='{.data.key}' | base64 -d)
curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen/Qwen3-4B-Instruct-2507",
       "messages": [{"role": "user",
                     "content": "Suggest one day trip from Lisbon."}]}'
```

You should get an answer in the OpenAI format. Then look at vLLM's numbers (with the tunnel still open):

```bash
curl -s http://localhost:8000/metrics \
  | grep -E "num_requests_(running|waiting)|kv_cache_usage_perc"
```

<Note>

**On Azure with KAITO,** the Service is named after the workspace and listens on port 80, and KAITO sets no API key. Use `kubectl port-forward svc/workspace-phi-4-mini 8000:80`, then send the same curl without the `Authorization` line and with `"model": "phi-4-mini-instruct"`. Because there is no key, keeping this Service private matters even more.

</Note>

## Step 4: point Botley at it

Botley runs in the same cluster or the same private network. Change its two settings (Chapter 6). These are the values for the GKE and EKS recipes. On Azure, use `http://workspace-phi-4-mini.default.svc.cluster.local/v1` and the model name `phi-4-mini-instruct`, with no key.

| Setting | Value |
|---|---|
| Model address | `http://vllm.models.svc.cluster.local/v1` (inside the cluster) |
| Model name | `Qwen/Qwen3-4B-Instruct-2507` |
| API key | the key from the `vllm-api-key` secret |

Don't give the Service a public address. Only Botley needs to reach it.

<Careful>

**This is a starting point, not production yet.** Before real users depend on it, add the pieces from Chapter 7: weights stored close by, autoscaling on vLLM's metrics, monitoring and alerts. Then run Botley's real tasks against the new model and compare the results with the old one (Chapter 11).

</Careful>

<NoSillyQuestions>

<QA q={"Why does the first start take so long?"}>

The cluster may need to create a GPU machine, then pull a large image, then download about 8 GB of weights, then load them into the GPU. Later starts on a machine that already has the image are faster.

</QA>

<QA q={"Can I use a bigger model with the same file?"}>

Yes. Change `--model`, choose GPUs with enough memory (Chapter 4), and set `--tensor-parallel-size` and `nvidia.com/gpu` to the number of GPUs per copy. For a gated model, add a Hugging Face token as a secret and pass it as `HF_TOKEN`.

</QA>

<QA q={"Why does the Azure recipe use a different model?"}>

KAITO's simple path only works with its own list of presets. You can serve other models with KAITO too, or use `vllm.yaml` on AKS as the note says.

</QA>

<Takeaways>

- The same `vllm.yaml` works on GKE and EKS. Only the node selector changes.
- On GKE Autopilot, a node selector for `nvidia-l4` is enough to get L4 machines with drivers.
- On EKS, check that each node shows an allocatable `nvidia.com/gpu`.
- On AKS, the KAITO add-on deploys preset models with vLLM from one short file.
- Use a fixed vLLM version, an API key, a long startup probe and shared memory.
- Keep the model private, test with port-forward, then point Botley at the in-cluster address.

</Takeaways>
